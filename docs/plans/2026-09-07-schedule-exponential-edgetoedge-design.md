# Дизайн: Редактирование расписания, индивидуальные рамки интервенций, экспоненциальный рост, быстрый выход и безрамочный экран

## 1. Введение и цели
Цель данного обновления:
1. **Редактирование расписания**: дать пользователю возможность редактировать существующие расписания блокировок и интервенций (изменять название, время начала/окончания с точностью до минут, дни недели, состав приложений и их настройки).
2. **Индивидуальные рамки интервенций в расписании**: поддержка двух типов расписаний (`HARD_BLOCK` — полная блокировка и `INTERVENTION` — интервенция по расписанию). В режиме интервенций для каждого выбранного приложения можно задать персональные секунды ожидания (например, 15с вместо стандартных 10с) и интервал повторного перехвата (например, 1 мин вместо 5 мин).
3. **Экспоненциальный рост времени ожидания**: увеличение длительности паузы при частых повторных открытиях приложения за заданное скользящее окно (например, 1 час). 
4. **Интерактивный предпросчет**: калькулятор в настройках приложения, отображающий таблицу времени ожидания для первых 10 последовательных открытий.
5. **Кнопка быстрого выхода во время дыхания**: возможность нажать «ВЫЙТИ» прямо во время фаз вдоха и выдоха, чтобы не ждать окончания таймера, если пользователь передумал заходить в приложение.
6. **Поддержка безрамочных экранов**: полное заполнение матрицы дисплея (Edge-to-Edge, включая область вокруг выреза камеры/челки и жестовой панели навигации) фоном и дыхательной анимацией без черных полос.

## 2. Архитектура и модель данных

### 2.1. Расширение модели расписаний
В `io.ronesec.android.domain.model.BlockSchedule` и `BlockScheduleEntity`:
- `scheduleType: ScheduleType`: перечисление `HARD_BLOCK` (полная блокировка) и `INTERVENTION` (интервенция по расписанию).
- `appOverridesJson: String?`: сериализованный словарь переопределений для каждого приложения:
  ```json
  {
    "com.zhiliaoapp.musically": {
      "durationMs": 15000,
      "reinterventionMs": 60000
    }
  }
  ```
- Вспомогательный класс `ScheduleAppOverride(val durationMs: Long?, val reinterventionMs: Long?)`.
- Обратная совместимость: для существующих расписаний по умолчанию тип = `HARD_BLOCK`, переопределения = `null`.

### 2.2. Расширение настроек целевых приложений
В `io.ronesec.android.domain.model.TargetApp` и `TargetAppEntity`:
- `exponentialGrowthEnabled: Boolean = false`
- `growthPercent: Int = 20` (шаг от 5% до 100%)
- `growthPeriodMinutes: Int = 60` (окно учета: 15м, 30м, 60м, 120м, 1440м)

### 2.3. Хранилище и DAO (`OpenAttemptDao`, `RonesecRepository`)
- Метод в DAO: `getRecentAttemptsCount(packageName: String, sinceTimestamp: Long): Int` для быстрого подсчета количества открытий за скользящее окно `now - periodMinutes`.
- Логика расчета итогового времени в `RuleEngine`:
  - Базовое время $T_{\text{base}}$: берется из расписания (если для приложения задан оверрайд) либо из настроек приложения.
  - Если экспоненциальный рост включен:
    $$N = \text{попытки за период}$$
    $$T = T_{\text{base}} \times \left(1 + \frac{\text{growthPercent}}{100}\right)^N$$
    Время округляется до целых секунд (или 1 знака после запятой) и передается в `InterventionConfig`.

### 2.4. Экспоненциальный рост при повторных перехватах (реинтервенциях)
В `AppMonitorService`:
- При наступлении каждого последующего цикла реинтервенции (во время непрерывного использования приложения), если `exponentialGrowthEnabled == true`:
  - Длительность паузы вычисляется как:
    $$T_{\text{next}} = \min\left(300\,000\text{ мс}, T_{\text{current}} \times \left(1 + \frac{\text{growthPercent}}{100}\right)\right)$$
  - Экран реинтервенции отображается с увеличенной длительностью паузы $T_{\text{next}}$.
  - При нажатии «ПРОДОЛЖИТЬ» следующий таймер реинтервенции планируется с этой обновленной конфигурацией.
  - При выходе из приложения (`recordExit`) или выключении экрана (`ACTION_SCREEN_OFF`) цепочка сбрасывается.

## 3. Пользовательский интерфейс (UI)

### 3.1. Экран блокировок (`BlocksScreen.kt`)
- Добавление кнопки **«РЕДАКТИРОВАТЬ»** на карточке каждого расписания.
- Диалог создания/редактирования расписания (`ScheduleEditorDialog`):
  - Переключатель режима расписания: `ПОЛНАЯ БЛОКИРОВКА` vs `ОСОБЫЕ ИНТЕРВЕНЦИИ`.
  - При выборе режима `ОСОБЫЕ ИНТЕРВЕНЦИИ`: под каждым включенным приложением раскрывается плашка настройки:
    - Секунды паузы: кнопки `-5с`, `-1с`, `+1с`, `+5с` и поле ввода.
    - Интервал повторного перехвата: чипы `1м`, `3м`, `5м`, `10м`, `Выкл` или ручной ввод.
  - Поддержка сохранения изменений существующего расписания по его `id`.

### 3.2. Экран настроек приложения (`TargetSettingsScreen.kt`)
- Карточка **«ЭКСПОНЕНЦИАЛЬНЫЙ РОСТ»**:
  - Тумблер активации.
  - Настройка процента: степперы `-5%`, `-1%`, `+1%`, `+5%`, чипы `10%`, `20%`, `30%`, `50%`.
  - Выбор периода: `15м`, `30м`, `1ч`, `2ч`, `24ч`.
  - **Интерактивный предпросчет**: таблица с 10 строками (открытие 1..10 и расчетное время задержки в секундах).

### 3.3. Экран интервенции (`InterventionOverlayView.kt` и `OverlayController.kt`)
- **Кнопка «ВЫЙТИ» во время дыхания**:
  - Отображается внизу во время фаз «ВДОХ» и «ВЫДОХ».
  - По нажатию: закрывает оверлей, делает `GLOBAL_ACTION_HOME`, фиксирует `AttemptOutcome.ABANDONED`.
  - Кнопка «ПРОДОЛЖИТЬ» появляется только по завершении таймера (`AnimationPhase.COMPLETE`).
- **Безрамочный Edge-to-Edge**:
  - В `OverlayController`:
    - `params.layoutInDisplayCutoutMode = WindowManager.LayoutParams.LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES` (для API >= 28).
    - `FLAG_LAYOUT_IN_SCREEN`, `FLAG_LAYOUT_NO_LIMITS`, `FLAG_DRAWS_SYSTEM_BAR_BACKGROUNDS`.
    - Прозрачные системные панели.
  - Фон и `Canvas` дыхания занимают 100% экрана, а текстовые и интерактивные элементы имеют безопасные отступы `WindowInsets.systemBars`.
