# Дизайн: Отключение статистики на оверлее, произвольное время вдоха и блокировка по расписанию

## 1. Контекст и цели
Пользователь запросил 3 улучшения в приложении **wattim**:
1. **Отключение вывода статистики сэкономленного времени**: возможность скрыть мотивационную плашку сэкономленного времени жизни на экране паузы/дыхания.
2. **Произвольное время для вдоха**: возможность задавать точное пользовательское время длительности дыхательной анимации (паузы) вместо грубого шага `-2с / +2с`.
3. **Блокировка по расписанию (Hard Block)**: возможность настроить расписание (время с-по, дни недели, список приложений), в течение которого приложения жестко заблокированы без возможности продолжить.

---

## 2. Архитектура и изменения

### 2.1 Отключение статистики сэкономленного времени
- **Хранилище**: таблица `settings` в Room DB (`AppSettingEntity`). Ключ: `show_saved_time_stats` (по умолчанию `"true"`).
- **Экран настроек (`ConfigScreen.kt`)**: переключатель `TerminalBadge` / тумблер:
  * Текст: «ПОКАЗЫВАТЬ СБЕРЕЖЕННОЕ ВРЕМЯ НА ЭКРАНЕ ПАУЗЫ»
  * Значения: `ВКЛ` / `ВЫКЛ`.
- **Служба мониторинга (`AppMonitorService.kt`)**:
  * Перед вызовом `overlayController.showIntervention(...)` проверяется настройка `show_saved_time_stats`.
  * Если `"false"`, то `savedTimeText = null`.
- **Оверлей (`InterventionOverlayView.kt` / `InterventionOverlayContent`)**:
  * Если `savedTimeText == null`, баннер скрыт, экран чист и сфокусирован только на дыхании и фразе.

### 2.2 Произвольное время для вдоха (`durationMs`)
- **Экран настроек приложения (`TargetSettingsScreen.kt`)**:
  * Карточка «ДЛИТЕЛЬНОСТЬ ПАУЗЫ»:
    - Прямое поле ввода секунд (`BasicTextField` с фильтрацией цифр, `fillMaxWidth`, placeholder `"8"`).
    - Быстрые шаги: `-1с`, `+1с`, `-5с`, `+5с`.
    - Быстрые пресеты: `3с`, `5с`, `8с`, `10с`, `15с`, `20с`, `30с`.
    - Безопасный парсинг и валидация в диапазоне от `1с` до `120с` (или до 300с).
  * Анимации:
    - `FillAnimation`, `BreathingSphereAnimation`, `CircleParticlesAnimation` уже принимают `durationMs` и масштабируют кривые дыхания пропорционально.

### 2.3 Блокировка по расписанию (Hard Block)
- **Существующая основа**:
  * `BlockSchedule` (id, name, start: LocalTime, end: LocalTime, days: Set<DayOfWeek>, enabled: Boolean, packages: Set<String>).
  * `RuleEngine.kt` уже проверяет `activeSchedule` и возвращает `Decision.Block(until = todayEnd)` при совпадении дней и текущего времени.
  * `AppMonitorService.kt` при `Decision.Block` вызывает `overlayController.showBlock(...)`, где нет кнопки «ПРОДОЛЖИТЬ», только «ЗАКРЫТЬ И ВЕРНУТЬСЯ».
  * `BlockDao` и `RonesecRepository` уже содержат методы `insertBlockSchedule`, `deleteBlockSchedule`, `updateBlockSchedule`, `getBlockSchedulesFlow`.
- **Недостающий компонент**: UI для управления расписаниями в `BlocksScreen.kt`:
  * Кнопка **«+ СОЗДАТЬ РАСПИСАНИЕ»**.
  * Диалоговое окно создания расписания:
    - Поле ввода названия (например, «Рабочие часы», «Ночной фокус»).
    - Выбор времени начала и конца: часы и минуты (с проверкой перехода через полночь, например 23:00 - 07:00).
    - Выбор дней недели: Пн, Вт, Ср, Чт, Пт, Сб, Вс с быстрыми пресетами («Будни», «Выходные», «Все дни»).
    - Выбор блокируемых приложений: список чекбоксов из `targets` с возможностью «Выбрать все».
    - Кнопки «СОХРАНИТЬ» и «ОТМЕНА».
  * В списке расписаний:
    - Карточка каждого расписания с тумблером `АКТИВНО / ВЫКЛ`.
    - Кнопка удаления расписания (`УДАЛИТЬ`).
    - Отображение дней недели, времени и списка заблокированных приложений.

## 3. План тестирования и верификации
1. Unit-тесты на парсинг и логику расписаний (проверка `RuleEngine` на пересечение времени, ночные интервалы).
2. Unit-тесты на сохранение настройки `show_saved_time_stats`.
3. Запуск `./gradlew test` (все тесты зеленые).
4. Запуск `./gradlew assembleRelease` и проверка размера `wattim.apk`.
