# Wattim Android implementation plan

Build one native Android application with a pure Kotlin policy/state-machine module, a single service-owned protection coordinator, Room-backed coherent policy snapshots, and one shared Compose design system for Activity and WindowManager content. Keep platform effects outside the reducer. Preserve every Android capability in the supplied specification, including the features identified there as broken.

This document plans the implementation; it contains no application implementation. Product references below refer to [wattim-spec.md](wattim-spec.md). The engineering source used is the supplied archive actually present in this workspace, `android_agents_bundle_v1(1)(2).zip`: its `AGENTS.md`, context map, accessibility-protection profile, and architecture, concurrency, lifecycle, Room, Compose, UI design, performance, battery, testing, security, release, and review references. Templates and implementation workflows were unnecessary for this planning task. No old Wattim repository or old implementation was inspected.

Android scope is specification §§0–2 and Android/shared requirements in §§4–8. Section 3 and extension-only discrepancies in §8 do not introduce Android features. Engineering recommendations for generic light/dark UI, accessibility-overlay substitution, or volume fallbacks yield to the specified six Android palettes, application-overlay permission/behavior, and proper audio APIs. Historical Kotlin 1.9/schema-version/APK-size observations do not require legacy storage compatibility or an obsolete toolchain; API 29 minimum, application ID, ABI support, behavior, and visual tokens remain contracts.

**Rewrite/distribution boundary.** This plan is a clean implementation contract. It does not promise in-place migration from a pre-rewrite `ronesec.db` or compatibility with an unknown historical signing key unless a separate upgrade requirement is added. Distribution policy is checked against current official requirements at implementation/release time; store-policy compliance may constrain release configuration, but it must not silently change Wattim product behavior or add user-facing flows outside the specification.

## 1. Architectural invariants

| ID  | Rule and enforcement boundary                                                                                                                                                                                                                                                                                                                                                                            | Bug or regression prevented                                                                                                         |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| I1  | `InterventionCoordinator` is the only writer of protection/session/runtime state. `PolicyStore` is the only durable policy mutation gateway; screen ViewModels own only presentation/drafts. Expose immutable values.                                                                                                                                                                                    | Service, timer, UI and repository racing to grant access or recreate an overlay.                                                    |
| I2  | Events → pure reducer → immutable state and typed effects. Neither Canvas nor Room nor audio callbacks call policy or show windows directly.                                                                                                                                                                                                                                                             | Hidden policy paths, nonreproducible transitions, audio workarounds changing navigation.                                            |
| I3  | Every asynchronous result carries process/service generation and appropriate session, attempt, operation, policy revision and/or boundary identity. Check identity at consumption and immediately before platform execution.                                                                                                                                                                             | Old Continue, dismiss, revoke, query, timer or focus callback affecting a new session.                                              |
| I4  | All jobs have an owner and cancellation path. Cancellation supplements identity checks. Protection ingress is bounded: lossless low-volume control events are serialized, foreground evidence is transition-aware/coalescible, and overload yields a tagged resynchronization instead of unbounded queue growth. The coordinator does not await database/platform round trips inside its event consumer. | Leaks, blocked foreground processing, late effects after destruction, or memory/battery blow-ups during Accessibility event storms. |
| I5  | Domain rules use immutable inputs and injected time; no Android, Room, Compose, Context or dispatchers inside policy/reducer code.                                                                                                                                                                                                                                                                       | Untestable schedules, main-thread I/O and platform behavior leaking into precedence.                                                |
| I6  | `Loading` is distinct from `Ready(empty)`. A decision uses one committed policy revision plus coordinator-owned ephemeral state. Backoff receives real prior-opening history.                                                                                                                                                                                                                            | Startup protection bypass, torn schedule/override/grant state, permanently zero backoff.                                            |
| I7  | Only durable semantics survive restart. Session identity/permits, Quick Return exit times, overlay phase, dialogs, jobs and audio ownership never enter Room. Durable access is acknowledged only after commit.                                                                                                                                                                                          | Accidental permanent permits, false saved-time statistics and imaginary persistence.                                                |
| I8  | Half-open intervals and explicit wall/monotonic clock roles govern every deadline. A deadline event triggers fresh evaluation; it never directly grants/shows.                                                                                                                                                                                                                                           | Midnight/DST errors, clock-change drift, expired grants winning timer races.                                                        |
| I9  | At most one real overlay window and one audio lease. Showing the same session updates content; dismiss/release require matching ownership. `Exiting` persists until departure is confirmed.                                                                                                                                                                                                              | Duplicate overlays, target exposure during Exit, stale same-package reopen.                                                         |
| I10 | No INTERNET permission, network client, telemetry, tracking SDK, remote sync, cloud backup of app data, screen-content reading or input capture. Local journal contains transition metadata only.                                                                                                                                                                                                        | Privacy contract violated through dependencies, backup or diagnostics.                                                              |
| I11 | All Feature Coverage Matrix entries have one primary stage, owner, test and acceptance condition. Broken legacy behavior is repaired without losing its capability.                                                                                                                                                                                                                                      | Small features, grants, schedules and edge cases silently dropped.                                                                  |
| I12 | Exactly one eight-token registry represents all six Android themes. All surfaces and animation colors consume it; exact typography/component states are shared.                                                                                                                                                                                                                                          | Material defaults, palette drift, overlay/theme mismatch or lost animation modes.                                                   |

## 2. Final architecture

### 2.1 Boundaries and project tree

Use two production Gradle modules: `:domain` is Kotlin/JVM so the policy and race tests cannot acquire Android dependencies; `:app` owns Android, Room, Compose and composition. Use constructor injection and a small application composition root, without a DI framework, generic use-case layer, navigation graph framework or repository per table. The app has one Activity; detail routes are explicit immutable navigation state as in §2.8.

```text
settings.gradle.kts / gradle/libs.versions.toml / gradlew
domain/src/main/kotlin/io/ronesec/domain/
  model/                 TargetConfig, policy snapshots, grants, attempts, clocks
  policy/                RuleEngine, PolicyCompiler, ScheduleResolver, Backoff
  protection/            ProtectionState, Event, Effect, Reducer, session identities
  breathing/             BreathingTimeline (phase/progress/completion mathematics)
domain/src/test/          Policy fixtures, transitions, temporal and accounting contracts
app/src/main/
  AndroidManifest.xml    Spec permissions/components; offline/release constraints
  kotlin/io/ronesec/android/
    WattimApplication    Constructor wiring and process-scoped store lifetime
    data/                WattimDatabase, entities/DAOs, PolicyStore, StatisticsStore
    protection/          InterventionCoordinator, EffectExecutor, EventJournal
    platform/
      accessibility/     AppMonitorService, EventIngress, ForegroundTracker, SubscriptionController
      overlay/           OverlayHost, OverlayLifecycleOwner, OverlayPresenter
      audio/             AudioGuard
      time/              AndroidClocks, TemporalBoundaryScheduler
      system/            PermissionMonitor, PackageCatalog, BootReceiver,
                         FocusForegroundService and service status
    ui/
      MainActivity       singleTop, adjustResize, Activity result/settings adapters
      AppRoute           Four tabs, detail origin, onboarding/ready routing
      onboarding/        OnboardingViewModel, permission steps and ready content
      home/              HomeViewModel, HomeScreen, AddAppDialog
      target/            TargetSettingsViewModel, form, PreviewDialog
      blocks/            BlocksViewModel, ScheduleEditorViewModel, session/cards/editor
      stats/             StatsViewModel, StatsScreen and duration formatting
      config/            ConfigViewModel, ConfigScreen
      intervention/      Shared InterventionContent, BlockContent, EmergencyDialog
      designsystem/      ThemeId, WattimColors, ThemeRegistry, WattimTheme,
                         typography/dimensions, Terminal components, animation drawing
  res/values*/            English/Russian strings, theme-independent Android resources
  res/xml/               Accessibility config, backup/data-extraction exclusions
app/src/test/             Coordinator/fake-adapter, repository and ViewModel tests
app/src/androidTest/      Room, Compose, actual overlay/platform/lifecycle checks
app/schemas/              Exported Room schemas; migrations added with future changes
```

Dependency direction: `app/data → domain/model`; `app/protection → domain/protection + narrow effect ports`; platform adapters implement those ports; UI ViewModels depend on stores/domain values, never service objects; designsystem depends only on Compose and its own immutable tokens; `ui/intervention` is reusable by Activity preview and overlay. The composition root connects adapters to the coordinator. No screen imports another screen's ViewModel. `StatisticsStore` owns SQL reads/format-independent aggregate results, not another policy cache. Interfaces exist for clock, durable effect sink and Android effect boundaries where fakes provide real value. Ownership must not collapse into god objects: `InterventionCoordinator` owns ordering and state transitions but delegates pure reduction, effect execution, identity creation, boundary planning and journaling; `PolicyStore` owns durable serialization/publication but delegates command transaction code, snapshot reads and policy compilation. Split by responsibility when a component starts implementing another owner's algorithm, not by arbitrary file-count or LOC quotas.

### 2.2 Mutable state and lifetimes

| State                                                                                                | Sole owner / lifetime                                                                  | Inputs and observers                                                                                 | Restart semantics                                               |
| ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Committed policy data/revision                                                                       | `PolicyStore`, lazily started process scope while a service or UI client needs it      | Serialized mutation commands; Room → committed snapshot; coordinator and ViewModels observe          | Room restored before Ready                                      |
| Protection machine, foreground evidence, session permits, last exits, pending effects/history deltas | `InterventionCoordinator`, one `AppMonitorService` connection generation               | Mailbox only; publishes RuntimeState, protection/status flows                                        | Discard on disconnect/process death; no resurrected session     |
| Foreground ingress / normalization watermark/cache                                                   | `EventIngress` + `ForegroundTracker`, service connection                               | Lossless control events; transition-aware foreground evidence; bounded resync results to coordinator | Reset generation; clear pending coalescer state and resync      |
| Subscription applied configuration                                                                   | `SubscriptionController`, service connection                                           | Desired enabled packages/active tracking from coordinator                                            | Reapply on reconnect                                            |
| Nearest boundary job/token                                                                           | `TemporalBoundaryScheduler`, child of coordinator                                      | Current temporal inputs; emits tagged boundary event                                                 | Cancel/rederive; never restore a job                            |
| Attached window, composition lifecycle/store                                                         | `OverlayHost`, service connection; one attachment lease                                | Desired state/effect identity; overlay callbacks become events                                       | Destroy and recreate only for a new attachment                  |
| Overlay presentation and emergency-open/focus state                                                  | `OverlayPresenter`, attachment/session lifetime                                        | Coordinator state plus presentation settings and aggregate stream                                    | RAM only; theme/locale changes preserve state                   |
| Audio focus request and pause job                                                                    | `AudioGuard`, one overlay lease                                                        | Acquire/release commands, focus callback events                                                      | Cancel retries and abandon focus on release                     |
| Permission observation/status and metadata caches                                                    | `PermissionMonitor`/`PackageCatalog`, process objects with client-scoped registrations | System callbacks/resume; immutable status/catalog                                                    | Read live, never restore a permission Boolean as authority      |
| FGS notification/status                                                                              | `FocusForegroundService`, its own service lifetime                                     | Connection/pause/readiness status flow                                                               | Restart visible service legally; no policy duplication          |
| Screens, navigation and editor drafts                                                                | Route/ViewModels; `SavedStateHandle` for route/package ID and small drafts             | Typed user actions; store flows                                                                      | Restore draft/navigation, reread committed data and permissions |
| Frame progress and visible countdowns                                                                | Visible composition child jobs                                                         | Shared monotonic timeline or current durable deadline                                                | Cancel when not visible; resample rather than replay ticks      |
| Transition journal                                                                                   | Coordinator, 256-entry ring                                                            | Reduced transitions/effect outcomes                                                                  | RAM only; explicit local JSON diagnostic export                 |

## 3. Protection pipeline

### 3.1 Data flow and serialization

```text
TYPE_WINDOW_STATE_CHANGED / screen / reconnect / user / boundary callbacks
                  │ copy primitives; tag generation/source sequence
                  ▼
             EventIngress
        ┌─────────┴──────────┐
        │                    │
 lossless control      foreground evidence
 events                 transition-aware/coalescible
        │                    │ overflow/ambiguity → ResyncRequired once
        └─────────┬──────────┘
                  ▼
       serialized ProtectionEvent consumer — no database waits
                  │
PolicyStore ── PolicyCommitted(revision, snapshot) ──┤
                  ▼
 InterventionCoordinator: RuntimeState + session machine
                  │
         pure Reducer → RuleEngine / ScheduleResolver / Backoff
                  │ new state committed before effects are dispatched
                  ▼
 typed effects ──┬── Main.immediate: window, focus, HOME, service subscription
                ├── owned delay: nearest temporal boundary → tagged event
                └── serialized store writer: transaction → tagged commit/failure
                  │
   OverlayPresenter → immutable OverlayUiState → shared WattimTheme + content
                  └── user actions return to the same mailbox
```

The service copies event type, package, window ID and source uptime; it does not retain `AccessibilityEvent` or node objects. Reception also samples wall time and elapsed realtime once. Source `eventTime` uses uptime and is **not** numerically compared with elapsed-realtime deadlines. Source watermark rejects older same-generation evidence; arrival sequence orders independent event sources. The coordinator runs one light consumer on injected `Main.immediate`; the domain reducer remains dispatcher-free. Main-owned platform calls are short; Room and metadata scans cannot run in this consumer.

`EventIngress` replaces an unbounded mailbox while preserving the specification's single serialized consumer. Low-volume control events (`Exit`, `Continue`, emergency actions, screen/service lifecycle, policy commits and temporal boundaries) are lossless and must never be silently dropped. Foreground evidence is copied to primitives before ingress and may be deduplicated/coalesced only when doing so cannot erase a confirmed `A → B → A` transition. If foreground capacity is exhausted or evidence becomes ambiguous, mark the foreground state dirty and enqueue one identity-tagged `ResyncRequired`; the bounded resync in §3.2 establishes the authoritative focused package before further protection decisions. No coroutine is launched per ordinary Accessibility callback. Measure ingress high-water/overflow-resync counts under stress; sustained overload is a producer/filtering defect, not a reason to grow memory without bound.

`RuntimeState` is consumed synchronously. An enabled-target entry receives a unique session `(processNonce, serviceGeneration, entryCounter)` and attempt cycle ID. Every real departure ends that session, revokes its RAM permit, records a monotonic exit time, cancels its deadlines/effects and releases its window/audio. Reintervention creates a new attempt cycle in the same foreground session; duplicate events and policy re-evaluation do not.

### 3.2 Foreground normalization and ambiguous transitions

Use `TYPE_WINDOW_STATE_CHANGED` only for ordinary detection. Ignore `TYPE_WINDOWS_CHANGED`, content/text/input events and overlay-generated window changes as package-entry authority (§2.4.2 wins over §5's general wording). Cache launcher and enabled IME package identities; distinguish system/IME windows using window metadata. Do not rely only on `keyboard`/`inputmethod` substrings, which can exclude a legitimate target. Own overlay windows are noise; **the real MainActivity becoming foreground is a target departure**, despite the broad self-package filter described in the old behavior.

On reconnect, unlock, target subscription change, ambiguous system-window return, and first apparent reopen after Exit, perform one bounded foreground resync. Inspect active/focused application-window metadata and, only if package metadata requires it, the root node's package identity; never read text, children, content descriptions, screenshots or input. Release node/window references immediately. Enable the minimum XML retrieval capability needed for this metadata-only path. Match event/window IDs and exclude the overlay, IME, SystemUI and keyguard. In multiwindow use the focused application window; if there is no trustworthy candidate, retain `Unknown` and wait for fresh evidence instead of inventing an entry.

This exceptional metadata IPC is outside the ordinary in-memory policy hot path. Resync results carry generation/request sequence and cannot overwrite newer evidence. System dialogs and notification shade cause ambiguity/resync, not automatic new sessions; confirmed app departure invalidates a permit. Screen lock always suspends. The window retrieval flags and `packageNames`/`notificationTimeout` behavior must follow the [AccessibilityServiceInfo API](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo); the distinction between state and hierarchy events follows [AccessibilityEvent](https://developer.android.com/reference/android/view/accessibility/AccessibilityEvent).

These are substates, not independent flags. `Granted` also represents a tracked enabled target allowed by pause/grace without a permit. Presentation changes do not constitute a protection transition.

## 4. Product policy and time model

### 4.1 Exact precedence and conflicts

`RuleEngine.evaluate(package, temporalContext, RuntimeState, priorEntryCount)` has exactly `Allow(reason)`, `Block(until)` and `Intervention(config)`. Reasons are `NOT_TARGET`, `TARGET_DISABLED`, `GLOBAL_PAUSE`, `ACTIVE_SESSION_PERMIT`, `ACTIVE_TIMED_PERMIT`, `QUICK_RETURN`. Always execute the explicit ordered checks in §1.2, not the shorthand “six levels” in §7.

| Ordered condition                            | Decision / conflict resolution                                                                  | Consequence                                                                               |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 1. Active global pause, finite or indefinite | Allow GLOBAL_PAUSE, even during a manual/scheduled block                                        | Expiry/resume reevaluates the foreground target; indefinite pause has no expiry job       |
| 2. Missing target; then disabled target      | Allow NOT_TARGET / TARGET_DISABLED                                                              | Grants and schedule membership cannot protect a disabled/removed target                   |
| 3. Matching active manual session(s)         | Block until maximum matching end                                                                | Beats all schedules/grants/grace; recalculate at that end before exposing target          |
| 4. Active HARD_BLOCK occurrence(s)           | Block through union of overlapping/touching hard-schedule intervals                             | Beats intervention schedules and all grants; never select arbitrary DAO row               |
| 5. Active INTERVENTION schedule              | Valid session permit, then valid timed permit, then grace; otherwise scheduled config + backoff | Override only duration/reintervention; inherit phrase, animation, grace and growth fields |
| 6. No intervention schedule; valid grants    | Session reason first, timed reason second                                                       | Both must match package/identity/type and strict expiry rules                             |
| 7. Quick Return elapsed < configured grace   | Allow QUICK_RETURN                                                                              | Manual/hard schedules still win; no new permit is manufactured                            |
| 8. Remaining enabled target                  | Base-config Intervention + backoff                                                              | Scheduled inactivity never turns normal protection off                                    |

Manual block precedence retains §1.2's explicit maximum manual end even if a schedule extends beyond it. At that boundary the active schedule takes over with no detach/audio release gap. Scheduled hard-block unions compute the complete currently connected interval; a continuously covered weekly pattern yields `until = null` with a blocked-state label, not an invented finite end. Evaluate later schedule starts as boundaries even when a current permit exists.

For overlapping INTERVENTION schedules, choose the active occurrence with the latest start instant; ties use stable schedule ID ascending. Apply both override fields from that single winning schedule, falling back individually to target defaults. This deterministic interpretation preserves every schedule's capability without mixing contradictory configurations. A newly starting winning schedule replaces effective config; its end falls back to the next active schedule or base config.

### 4.2 Calendar schedules and manual sessions

Store weekday membership as a seven-bit mask and start/end as local minute-of-day. Selected weekday denotes the **start day**: Monday 23:00–07:00 covers Monday 23:00 through Tuesday 07:00, not Monday morning. Occurrences are `[start, end)`. Equal start/end is invalid, with inline validation; no hidden all-day interpretation. Resolve with the current system `ZoneId`; wall-clock/timezone changes recompile affected intervals immediately. Use `java.time`, never fixed 24-hour subtraction for yesterday/tomorrow.

DST decision: nonexistent local boundaries move forward by the gap using zone rules; ambiguous start uses the earlier instant and ambiguous end the later instant, covering the intended repeated local period. An occurrence that becomes empty after gap adjustment contributes no active interval. A pure resolver checks previous/current start days and enough subsequent weekly occurrences to find the next relevant boundary/continuous union. Tests include Sunday→Monday and both DST transitions.

Quick Focus and Quick Lock create explicit package memberships with wall-clock start/end and active flag. No dynamic “all apps forever” membership: selecting all snapshots the current targets. Quick Lock creates a single-target session; Quick Focus creates one for selected targets. Quick Lock is a route capability, not a property of `TargetSettingsScreen`: only a caller that explicitly supports hard-block launch passes `canQuickLock=true`; Home-origin must not acquire it implicitly. Product commands preserve the specification's singular active-session UX: while a manual block session is active, Blocks shows the one `ActiveBlockSessionCard` and does not expose the Quick Focus launcher; callers should not create another overlapping manual session. The RuleEngine nevertheless evaluates multiple matching persisted rows defensively and uses the maximum matching end so restored/corrupt/concurrent legacy data cannot create an unprotected gap. Stop deactivates the displayed active session. Empty selection disables launch; schedules require a name, weekday and at least one target. Disabled targets remain configurable/selectable but their OFF state wins policy.

### 4.3 Grants, Quick Return and reintervention

| Action/state                        | RAM state                                                                           | Durable state                                                                                                    | Expiry/leave/restart behavior                                                                                                     |
| ----------------------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Normal Continue, reintervention OFF | Session permit for current session, no deadline                                     | CONTINUED outcome only                                                                                           | Leave, screen off, disconnect or death removes access                                                                             |
| Normal Continue, reintervention > 0 | Session permit with elapsed deadline                                                | CONTINUED outcome only                                                                                           | Deadline triggers reintervention only while the same foreground session remains; departure removes access                         |
| Emergency “enter once”              | Session permit only; current reintervention deadline if enabled                     | CONTINUED outcome; **no** timed grant                                                                            | Ends on session exit/death or repeat deadline; does not silently become a 15-minute permit                                        |
| Emergency 15m/30m/1h                | Timed permission reflected in runtime; no shorter session permit that reopens early | `origin=EMERGENCY`, explicit selected expiry + CONTINUED atomically                                              | Survives departure/restart; chosen expiry outranks the shorter repeat interval, but not hard blocks                               |
| Emergency forever                   | Clear package's RAM permits and repeat deadline                                     | Set target enabled=false, revoke grant and resolve outcome atomically                                            | It is permanent **target disable**, not a null-expiry grant; re-enabling starts ordinary protection                               |
| Confirmed target exit               | Remove matching session permit; set `lastExitElapsed[package]`                      | Remove legacy `REINTERVENTION` grant; explicit emergency timed grants remain                                     | Quick Return is the only ordinary reopen allowance; grace is RAM-only and does not survive disconnect/death/screen off             |
| Expired timed grant                 | Policy ignores immediately; CAS cleanup may follow                                  | Delete only matching grant ID/version                                                                            | Cleanup timing never controls eligibility                                                                                         |

Normal Continue always grants access only to the current foreground session. A positive reintervention interval adds an elapsed-time deadline for that session; OFF leaves it without a deadline. After a confirmed departure, Quick Return alone decides whether an ordinary reopen is admitted without another intervention. Emergency once remains session-only, while an explicit emergency timed grant remains durable until its selected expiry.

A reintervention deadline always reevaluates current precedence. Global pause suppresses intervention until resume/expiry, hard blocks show block instead, and target disable cancels protection. Grace only originates at a confirmed departure; it never refreshes on a duplicate event, overlay attachment or foreground noise. Grace begins after explicit Exit confirmation too, preserving the specified quick-return behavior for a deliberate fresh reopen. Stale callbacks cannot consume grace as a fictitious new opening.

Session repeat time begins when the user action is accepted. Changing base/schedule reintervention applies to future session permits; an already-issued explicit emergency timed grant keeps its expiry. A changed HARD_BLOCK/global-pause/target-enabled policy takes effect immediately. Changing visible intervention duration/config preserves the original breathing start, updates its effective duration/deadline from the current winning config and the attempt's pinned prior-entry history, and never increments the attempt again. Theme/language changes cannot change that deadline.

### 4.4 Backoff and attempt accounting

Use Android defaults from §2.3: Russian default phrase exactly as supplied, FILL, **8 seconds**, repeat 5 minutes, grace zero, growth disabled, growth 20%, window 60 minutes. Android's specific 8 seconds wins over §1.3's general 10-second example. Persist custom phrase text unchanged when language changes.

For the nth backoff-eligible entry, `N` counts **prior genuine enabled-target ENTRY attempts while global protection was active** in `(now − growthWindow, now]`, excluding the current attempt ID. `NOT_TARGET`, `TARGET_DISABLED` and `GLOBAL_PAUSE` entries never increment backoff. Entries admitted by a valid permit or Quick Return still count as genuine openings of an enabled protected target; this is separate from whether an intervention is shown. Compute `clamp(round(Tbase × (1+r/100)^N), 1000, 300000)` milliseconds, using a saturation check before exponentiation can overflow. The first opening uses exponent zero. Schedule override duration is the base. Base duration editor remains 1–120 seconds; actual backoff may reach 300 seconds. Calculator and engine call the same pure formula; the calculator supplies N=0…9. Percent is 1–200; configured windows are the specified 15m/30m/1h/2h/24h.

The spec does not describe unfinished log rows or repeat accounting. Resolve explicitly: reserve one `open_attempts` row per genuine enabled-target entry, including entries admitted by a grant or Quick Return; exclude non-target/disabled entries and openings during `GLOBAL_PAUSE` from backoff eligibility. A global-pause entry may be retained as internal diagnostic evidence only if it is excluded from product attempt/backoff aggregates; do not let pausing protection create a later delay penalty. A new timer/schedule-triggered continuation challenge gets its own `kind=REINTERVENTION` attempt row so an earlier CONTINUED outcome is never overwritten. Displayed attempts are these entry/continuation decision opportunities; exponential growth counts **ENTRY only**, since §1.3 defines openings. Pure settings refreshes, duplicate events and changes within an existing challenge create no additional row.

Outcome begins unresolved, then becomes CONTINUED on accepted access, ABANDONED on explicit Exit/Cancel/Back or confirmed voluntary departure while awaiting a decision, or BLOCKED after block attachment succeeds. Completion alone is not CONTINUED. A block row stays BLOCKED when Exit follows. Screen-off/service failure/process-death during an unresolved challenge records internal `INTERRUPTED`; it is excluded from all user-visible attempt/continued/closed/saved statistics as well as saved-time calculations. It may remain available to diagnostics and lifecycle tests. Startup finalizes unresolved rows from dead generations as INTERRUPTED. Each `(sessionId, cycle)` is unique; terminal outcomes are immutable. In-memory reserved entries feed backoff immediately and are deduplicated against committed rows by attempt ID. A store failure is surfaced; do not manufacture a successful durable record.

Backoff eligibility is deliberately separate from statistics and raw foreground observation. Persist/compile an explicit eligibility bit or derive it deterministically from the decision context so a future query cannot accidentally count `GLOBAL_PAUSE`, disabled or non-target entries. Contract fixture: with growth enabled and global pause active, any number of target opens during the pause leaves the first post-resume backoff exponent unchanged; permit/Quick Return entries remain eligible openings unless the product specification is later amended.

## 5. Runtime state and persistence

### 5.1 Coherent RuntimeState

`RuntimeState` contains: readiness and durable revision; targets keyed by package; explicit grants; compiled manual-session membership and schedules/overrides indexed by package; global pause (`None`, `Until(Instant)`, `Indefinite`); retained recent ENTRY timestamp/ID index; coordinator-only session permits, last exit elapsed times and uncommitted history deltas. Keep presentation settings/theme/locale and statistics in separate immutable projections so a theme change or new statistic does not restart policy or recompile schedules. The coordinator joins committed policy and ephemeral values; the repository never owns mutable session permits.

`PolicyStore` serializes all policy-affecting commands. Initial and subsequent multi-table projections are read under a **single Room read transaction**, with one revision published after the corresponding write transaction. Do not `combine` independent table flows into a supposedly atomic snapshot: separate emissions may expose a removed target with old membership or a grant before its outcome. Use one policy invalidation trigger plus transactional projection; coalesce invalidations while a read is pending and discard older read generations. All writes route through the store, which publishes the committed projection before resolving the command. A runtime acknowledgement embeds that same revision/snapshot, making duplicate observer delivery harmless.

Initial loading includes the bounded recent-opening horizon (maximum currently supported 24h), all targets/configuration, grants and required schedule/manual-session data. Do not capture `now` once in a Room Flow and assume it expires records automatically. Evaluate expiration in memory on every event and scheduled boundary. Increasing a future supported growth window would require hydration before installing that policy revision; it cannot silently use an incomplete count.

While Loading, retain the latest confirmed foreground candidate and show honest loading status in Activity/notification. There is no temporary Allow result. After Ready, resync before showing protection. Android cannot guarantee interception before service/data readiness; measure this interval and never display protection as active during it. On initial storage failure remain Unavailable with retry/status; on later write failure keep the last committed snapshot, report error, and keep the applicable overlay. RAM-only Exit remains immediate. Target/settings saves and grants do not report completion until commit.

The hot path never calls a DAO, package-label/icon lookup, SQL statistics query, JSON parser or disk API. `PolicyCompiler` prepares immutable package indexes when policy changes. App metadata is supplied from stored target display names or lazy `PackageCatalog`; attempt history is loaded only for the needed rolling horizon, not all-time statistics.

Ownership does not imply monolithic implementation. `InterventionCoordinator` must remain orchestration-only: it sequences events, holds the machine and validates identities; reducer/policy math, effect execution, boundary calculation and journaling remain separate collaborators. `PolicyStore` remains the single serialization/publication facade, while SQL command transactions, snapshot projection and compilation stay separate components. Architectural review is triggered by responsibility leakage (for example, Coordinator starts implementing SQL or schedule math), not by an arbitrary LOC threshold.

Future changes require migrations, never destructive fallback. Timestamps are integer epoch milliseconds; durations use validated integer milliseconds; enum values have explicit stable storage identifiers. Room suspend queries use Room's executor; do not add redundant dispatcher hops.

## 9. Breathing animation

Preserve Android §2.9: three selectable styles and exactly one INHALE half followed by one EXHALE half. The broad four-phase concept in §0 and extension Hold/Rest phases do not replace Android behavior. `HORIZONTAL_SWEEP` and `VERTICAL_SWEEP` are conflicting, nonselectable legacy aliases (§§2.9/8); a clean model has only FILL/PULSE/CIRCLE. No required Android choice is removed and no extra animation choice is invented.

The timeline starts from matching **overlay-attached** acknowledgement, so time spent waiting to attach does not consume the user's breathing pause. Let `d` be effective duration, `e=max(0, elapsedNow-start)`, `t=clamp(e/d,0,1)`, `q=2t` for t<.5 else `2(1−t)`, and `p=3q²−2q³`. INHALE is t<.5, EXHALE is .5≤t<1, COMPLETE is e≥d. At completion hold zero breathing amplitude and stop continuous drawing. Countdown is `ceil(max(0,d−e)/100)/10` seconds, formatted SS.S; Continue eligibility is the exact `e≥d` check, not formatted zero.

| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FILL   | Draw bottom-aligned translucent rectangle of height `height*p`, with bright horizontal top boundary. Smoothstep gives a smooth turnaround at midpoint.                                                                                                                                        | Fill derives from accent at shared translucent opacity; boundary accent; background from theme.                                                                                                                                          |
| PULSE  | `R=.40*min(width,height)`; breathing radius `r=R*(.32+.68*p)`; draw core, two concentric soft halos and ring. The source's “35%/15%/base” description is underspecified: use outer halo opacity .15, inner .35, core strongest; all modulated by p, halo radii 1.35r and1.15r, ring radius r. | All circles/ring use accent with alpha, no gradient palette. One visible `withFrameNanos` loop samples the injected monotonic clock. Frame time is a callback cadence, not a separate timer epoch. Store high-frequency progress where Canvas draw reads it; only phase changes, countdown tenths and button eligibility invalidate their small semantic regions. The boundary scheduler and reducer use the same start/deadline; a frame may discover completion and emit an idempotent tagged event, but never independently grant access. No `delay(16)`, decremented counter, parallel animation-specific timers or per-frame DB/UI model rebuild.

Frame work is a child of attachment/session or preview composition; cancel on detach, screen off, suspension, destruction and session replacement. Theme, locale and emergency dialog visibility do not restart the loop. Config changes retain start and recalculate effective duration as §4.3; the emitted completion carries attempt/config identity. After returning from non-visible composition, sample current time rather than catch up ticks. Rendering follows display frames, with 60FPS verified on a 60Hz reference device; do not promise device-independent frame rates.

Respect reduced-motion/system animation-scale expectations: retain phase/countdown/required duration and all controls, but suppress spatial rotation/pulsation and render a static mode representative with phase updates. This is an accessibility rendering accommodation, not a shortened protection delay or removed selectable style. Preview uses exactly this timeline/drawing code with its own fakeable clock and no platform effects.

## 15. Implementation Agent Rules

1. The specification is a completeness contract, not a menu. Implement every F entry and all six themes, including all exact tokens and minor options.
2. Follow S01–S10 in dependency order. Maintain the F→owner→stage→test→DoD ledger; complete a row only after its verification criteria pass. S01 pins the current target SDK; S10 rechecks current distribution policy before shipment.
3. Preserve the decisions and I1–I12. Document and reconcile any necessary architecture change with all affected matrix/test entries before applying it; never silently change grant, time, lifecycle or visual semantics.
4. Add regression tests with bug-prone behavior: identities, Exit, grants, boundaries, readiness, persistence and live theme changes. Mandatory red tests block progression; compilation alone proves neither behavior nor completeness.
5. Keep domain policy free of Android/I/O, use the shared terminal components and theme registry, and keep all platform work owned/cancellable with symmetric cleanup.
6. Optimize only from measured evidence. Preserve all product behavior while reducing work; do not use performance or brevity as a reason to remove a feature/theme.
7. Build/install/test the release artifact and critical real-device flows. Record missing checks as unverified and keep the corresponding feature/stage/application open until they pass.
